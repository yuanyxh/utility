# 分享文章生成管线（SOUL.md + gen_article_generic.py）

## 背景
从作者 61 篇 mdx 博客提炼风格规范 SOUL.md，驱动独立脚本调 DeepSeek API（deepseek-v4-flash, temperature 0.8, max_tokens 16384, stream=False）生成技术分享文章。用脚本而非 agent 直写，避免 agent 上下文干扰。

## 关键文件
- `SOUL.md`：写作风格规范（61 篇 mdx 提炼），全文全角标点、第一人称骨架、架构师抽象、严谨硬朗正文
- `gen_article_generic.py`：通用版生成脚本（项目根），`--soul <SOUL.md> --src <素材> --out <输出>`
- `gen_article.py`：扫描器绑定版（内部迭代用），主题锚定扫描器文章，不可泛用
- `analyze_article.py`：统计脚本（/tmp，未归位），量化标点/字数/第一人称/句长/图表

## 泛化验证结论（2026-08-07）
- **10/10 达标**：跨主题域（工具架构/MCP 记忆/CSS 主题/PDA 扫码/Android 适配/请求封装/Agent 工作流/跨端项目总结）全部主题贴合素材、半角逗号贴汉字=0、mermaid+table 各一、无 ASCII、无罗列/口语/失真残留
- 确认 prompt 方案通用、非过拟合扫描器文章
- 前提关键判断：原 gen_article.py 有 4 处绑定扫描器（主题锚定/前言示范/Skills 案例/失真清单），直接跑别的素材会主题错乱，必须先写通用版

## 四层全角标点方案（v18 闭环）
1. SOUL.md 全文反引号外半角逗号转全角（风格文件本身成为全角样板）
2. gen_article.py 全部 prompt 中文后半角逗号转全角——`re.sub(r'([一-鿿]),', r'\1，')` 只命中中文后逗号，Python 语法安全，「n, 源码」这类前字拉丁字母的半角示例自动保留
3. 顶部硬规则内嵌示范句（全角形态示范）
4. user 第0条铁律（写完逐句自查，半角逗号即废稿）

## 架构师抽象四层约束（v19）
1. 顶部硬规则第3条：禁止罗列实现细节清单（类名/符号/正则/参数），抽象成「机制/模式/权衡」
2. QUALITY_PROMPT 第7条：从素材提炼 3~4 个「关键点」作为架构骨架（统一调度、按特征路由、优先级降级链、批量摊薄固定成本、全量兜底＋增量跟进、缓存与失效、无状态与幂等）
3. 禁令：禁止罗列实现细节
4. user 前言示范：「前一段时间我在做[这个项目/模块]，最核心的一件事是…——…，最终形成一个[产物]，供[使用方]用。」

## 量化指标口径（analyze_article.py）
- 半角逗号紧贴汉字 `[一-鿿],[一-鿿]`
- 第一人称/千字（原文基准 6.6）、平均句长（基准 60.9）
- 正文半角句号判定：grep `[\x{4e00}-\x{9fff}]\.` 为 0 即无违规（反引号内文件名 server.py/SKILL.md 的半角点不计）
- 10 篇观察点：平均句长 33~49 全部短于 v20 基准 60.9（严格化后句子更短更利落）；edge-to-edge 1643 汉字与 parallel 1762 略低于 1800 下限

## 迭代历史（v1-v20）
- v1-v6：第一人称密度修复（1.0→6.6 基准）、转折词、纠偏结构成型；「教结构」比「教数字」有效
- v7：解决主题跑偏（把 MCP 辅助功能当主扫描器写），加「文章质量」prompt + 注入项目真实事实源
- v9-v17：标点稳定输出中文全角；v17 首个全维度达标但含 4 处失真（泛化设计细节当真实落地）
- v19：用户批评 v18 吊儿郎当/前言废话/罗列符号，改造出四层约束
- v20：扫描器文章最终版达标

## 经验教训
- deepseek-v4-flash 对自然语言软风格约束执行不稳定（第一人称 v2=9.3/v3=2.2 波动大），硬规则+示范句比软约束有效
- 标点靠 SOUL.md 全文样例引导比规则文字有效
- 失真残留靠「真实落地 vs 泛化设计」区分清单治理（虚构/失真/未并入/未经统一验证/仅供参考/设计稿/泛化方案/历史方案一律不采用）
- 用户偏好：英文标点（, "）预留空格；记忆 content 首行「有背景时才记背景」，不是每条记忆都有背景
