# 变更审查

## 目标

在合并或发布前找出真实缺陷，而不是复述 diff。

## 规则读取

执行前读取 `.agent/rules/collaboration.md`、`design.md`、`testing.md`，以及变更范围对应的路径规则；文件不存在时跳过并说明。

## 步骤

1. **确定范围**：读取工作区状态、提交历史与 diff，区分已提交改动、未提交改动与用户既有改动。
2. **按优先级检查**：正确性、安全与隐私、数据一致性、错误处理、复用与抽象（重复实现、过早抽象、循环依赖）、测试覆盖、提交规范与原子性、格式化与 lint 结果、规则违背。
3. **验证假设**：能从代码、测试或命令确认的才报告；不确定的标注为待验证。
4. **输出发现**：按严重度排序，每条包含文件与行号、问题、触发条件、建议动作。
5. **结论**：明确可合并、需修改或阻塞。

## 完成条件

- 每条发现可定位到具体代码或提交。
- 提交信息符合规范，或已列出不合规项。
- 结论与发现一致。
- 已检查新增代码与既有实现的职责重叠，结论有依据。
- 未执行用户未授权的修改、提交或发布。

## 禁止

- 把风格偏好列为缺陷。
- 只报告问题而不给判定。
- 在没有授权时直接改代码或提交。
