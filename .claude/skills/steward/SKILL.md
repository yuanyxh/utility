# agent 环境体检

## 目标

发现并减少 agent 自身环境的腐化，不触碰业务代码。

## 完成标准

- 每条发现都有证据、严重度与建议动作。
- 已应用的变更都经用户确认且可回滚。
- 体检报告与 backlog 反映真实状态。
- 业务代码架构与死代码交给 `learn` 或 `review`。

## 执行前

阅读契约与 `.agent/agent-health.md`；任一缺失时说明缺口，只创建报告基线。阅读 `.agent/profile.yaml` 的节奏、过期阈值与维护模式。

## 步骤

1. **快照**：平台、模型、时间、git 分支与脏状态、报告年龄、配置的模式与节奏、可用证据源。
2. **盘点**：只列名称与路径，不复制内容：提示词与契约、规则、技能、记忆、钩子与自动化、MCP 服务、子代理、命令、插件、环境记录。
3. **确定性检查**：执行下表检查并记录命令输出。
4. **证据复核**：查看 git 历史、状态、决策、教训、记忆与会话记录（可用时），寻找重复修复、重复修正、被忽略的规则与错误技能选择。
5. **分级**：严重度 `blocker`、`high`、`medium`、`low`；置信度 `high`、`medium`、`low`；动作 `keep`、`merge`、`split`、`deprecate`、`move-to-trash`、`add`。
6. **确认与应用**：先展示发现，用户确认后再应用。移除的资产移到废纸篓或归档。不修改业务代码，不提交。
7. **记录**：向 `.agent/agent-health.md` 追加时间戳章节；延后工作写入 `.agent/backlog.md`；确认决策写入 `.agent/decisions.md`；更新 `.agent/.maintenance-state` 的 `last_run` 与 `pending`。
8. **节奏建议**：说明当前模式是否有效、下次检查日期。只有确认后才生成钩子、调度或自动化配置。

## 确定性检查

| 检查 | 证据 |
| --- | --- |
| 契约与 core 预算 | 行数与配置上限对比 |
| 重复或冲突 ID | 规则、技能、记忆标识重复 |
| 断引用 | 规则、技能、契约与资源路径无法解析 |
| 过期资产 | `review_by` 早于今天；版本过旧 |
| 记忆索引 | 索引行数、重复事实、无来源条目 |
| 泄漏 | 密钥、凭据、个人路径、主机名、内网地址模式 |
| 钩子健康 | 钩子文件存在、可执行、已注册 |
| MCP 健康 | 服务已声明、凭据只引用不写值、未使用服务 |
| 技能触发风险 | 描述长度、触发重叠、名称未出现在索引 |
| 环境陈旧 | 环境记录早于最近一次工具链变更 |

## 严重度

- `blocker`：agent 无法遵守契约，或关键资产损坏。
- `high`：规则冲突、密钥泄漏，或必需的钩子/MCP 服务失效。
- `medium`：陈旧或重复资产，浪费上下文或导致错误选择。
- `low`：外观、命名或文档漂移。

## 禁止

- 把业务代码腐化报告成 agent 环境腐化。
- 未经确认修改规则、技能、记忆、提示词或 MCP 配置。
- 原地删除资产，而不是移到废纸篓或归档。
- 把“已提醒”当作“已完成检查”。
- 提交变更。
