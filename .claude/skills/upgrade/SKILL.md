# 升级

## 目标

在可控风险下更新依赖、运行时与工具链，保持项目可持续维护。

## 规则读取

执行前读取 `.agent/rules/engineering.md`、`testing.md`；文件不存在时跳过并说明。

## 步骤

1. **盘点**：列出直接依赖、运行时与工具链的当前版本、最新版本与安全公告。
2. **分级**：补丁、次要、主要、破坏性四类；安全修复优先。
3. **计划**：一次只升一类；说明影响范围、所需代码改动与回滚方式。
4. **执行**：更新锁定文件，运行构建与测试。
5. **验证**：对比升级前后的测试、构建与关键路径结果。
6. **记录**：在 `.agent/decisions.md` 记录升级原因、版本与回滚点。

## 完成条件

- 每批升级前后均有可对比的验证结果。
- 破坏性变更已处理或明确记录未处理项。

## 禁止

- 一次性升级全部依赖。
- 在测试未通过时继续叠加升级。
- 跳过安全公告直接忽略高危项。
