# 持久上下文预检

这是所有会读取可选记忆或既往决策上下文的 skill 共用的前言。每个 `SKILL.md` 都链接到本文件，再补充自己的专属指引。

## 范围

当用户点名了记忆、某个既往决策或某个记忆路径，或项目暴露了一个明显的本地记忆摘要（`MEMORY.md` 或一个有文档记载的记忆目录）时，才读取持久上下文。先列标题，最多打开一到两份摘要；不要硬编码某个机器专属的记忆根目录，也不要读原始对话记录。把跨项目的条目当作可迁移的模式，而不是关于本项目的既定事实。

## 当前状态优先

当前的代码、diff、截图、日志、测试、文档、CI、远端状态和实时探测，永远优先于记忆，包括运行时自行注入的记忆。一条被记住的事实只是一条需要重新核实的线索，绝不是证据。当当前状态与某条记忆中的说法冲突时，点明该冲突，并遵循当前状态。

## 记忆不等于授权

记忆可以解释偏好，但绝不能授予或扩大对写入、提交、推送、发布、公开回复、删除或其他状态变更的授权。授权由当前轮次的指令和当前项目规则决定。像 `push` 或 `check` 这类历史措辞，是需要重新评估的上下文，不是可复用的动作令牌。

## 脱敏关卡

在把既往对话、持久记忆或跨项目笔记转成可复用的 Waza 指引时，只沉淀工作流规则。剥除原始对话文本、截图、本地路径、项目专属命令、issue 或 PR 编号、发布标签、commit 哈希、私有的产品边界、付费或授权细节、支持路由、用户名，以及单机状态。

如果确实需要一个示例，就使用中性的占位符，如 `ExampleCLI`、`ExampleApp`、`<issue>`、`<release>` 或 `<command>`。不要把某个私有的答复、维护者的回复、对截图的观察，或项目专属的事件，当作持久规则照抄。

每个 skill 都在这份参考之下补充自己的一段，用于该 skill 专属的覆盖与约束。
