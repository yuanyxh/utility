# 持久上下文预检

面向每一个会读取可选记忆或既往决策上下文的 skill 的共享前言。每个 `SKILL.md` 链接到本文件，然后追加该 skill 专属的指引。

## 范围

当用户点名记忆、某个既往决策或某个记忆路径，或项目暴露了明显的本地记忆摘要（一个 `MEMORY.md` 或一个有记录的记忆目录）时，读取持久上下文。先列出标题，最多打开一两个摘要；不要硬编码机器专属的记忆根，也不要读取原始转录。把跨项目条目视为可迁移的模式，而非关于本项目的既成事实。

## 当前状态优先

当前代码、diff、截图、日志、测试、文档、CI、远端状态与实时探测始终优先于记忆，包括运行时自行注入的记忆。记忆中的事实是要重新核实的线索，绝不是证据。当当前状态与某个记忆中的说法冲突时，点明冲突并以当前状态为准。

## 记忆不是授权

记忆可以解释偏好，但绝不能授予或扩大对写入、提交、推送、发布、公开回复、删除或其他状态变更的授权。当前轮次的指令与当前项目规则决定授权。像 `push` 或 `check` 这样的历史措辞是需要重新评估的上下文，不是可复用的操作令牌。

## 脱敏闸门

在把过往聊天、持久记忆或跨项目笔记转化为可复用的 Waza 指引时，只提炼工作流规则。剥离原始转录文本、截图、本地路径、项目专属命令、issue 或 PR 编号、发布 tag、commit 哈希、私有产品边界、付费或许可细节、support 路由、用户名，以及单机状态。

如果必须举例，请使用中立的占位符，如 `ExampleCLI`、`ExampleApp`、`<issue>`、`<release>` 或 `<command>`。不要把某个私人回答、维护者回复、截图观察或项目专属事故复制成持久规则。

每个 skill 在本参考之下追加自己的段落，用于 skill 专属的覆盖与约束。
