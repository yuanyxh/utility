# 专家评审者激活目录

编排者读取完整 diff 并运用判断（而非关键词匹配）来决定激活哪些专家。本目录定义了需要推理的信号。

## 常开（无需条件）

基础的 /check skill 常开运行。专家评审者是叠加的。

## 条件性专家

### 安全评审者

**Agent 文件:** `agents/reviewer-security.md`
**激活于:** Standard 或 Deep 深度

当 diff 改动了攻击者能够触及或影响的代码时激活：信任边界输入、鉴权或加密、凭据，或查询/shell/路径构造。

**不要**对以下情形激活：纯 UI 改动、配置文件更新、仅测试的改动、文档。

### 架构评审者

**Agent 文件:** `agents/reviewer-architecture.md`
**激活于:** Standard 或 Deep 深度

当 diff 改动了模块之间的关系时激活：边界、公开 API 或签名、跨模块依赖，或一个重大依赖，而非单个模块内部的逻辑。

**不要**对以下情形激活：单文件 bug 修复、新增测试、风格改动、文档更新。

## 对抗性审查（仅 Deep）

没有专用的 agent 文件。当环境具备 agent 能力时，编排者把四个角度作为并行 agent 运行，彼此看不到对方的发现；否则，它会在收集完所有发现之后再跑一遍额外的推理。

**激活于:** 仅 Deep 深度；Deep 的判据在 SKILL.md 的范围表中。

对抗性审查问：「如果我想要通过这个特定 diff 破坏这个系统，我会怎么做？」

四个攻击角度：
1. **假设违反** —— 这段代码假设什么永远为真？（格式、顺序、范围）当它不为真时会发生什么？
2. **组合失效** —— 当这段新代码在并发负载或部分失败之下与既有系统交互时，什么会坏掉？
3. **级联构造** —— 怎样的一串合法操作会导致一个非法状态？
4. **滥用场景** —— 在第 1000 次请求时、在一次部署期间、当两个用户同时编辑同一资源时，会发生什么？

报告对抗性发现时附上置信度分数；抑制阈值在 SKILL.md 的对抗性审查一节中。
