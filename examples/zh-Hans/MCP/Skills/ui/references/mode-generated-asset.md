# 模式：生成式图片素材

用于那些以生成方式产出、而非用代码排布的图表、架构插画、封面与社交卡片。这个模式要阻止的失败是否决循环：生成、得到「丑」、调个颜色、再生成，七轮之后才发现分歧从来不在题材上。

## 先写规格，再谈像素

在生成任何东西之前，先写出规格并拿到批准。六行，不多：

- **一句话说明这张图在主张什么。** 不是主题，是主张。「一个清理 Mac 的终端工具」是一个主张；「架构图」是一个主题。
- 画面中**每一段文字的语言**。
- **长宽比与它将在哪里被看到**（README 头部、社交预览、发布正文、文档内嵌）。在它出现的最小位置上的可读性，是决定字号大小的约束。
- **配色数量**，用一个数字写明。生成式图片默认的颜色数往往多于一张图表能承载的。
- **参考**：一张用户已接受的既有图片，或一个其素材风格要与之并列的被点名产品。
- **不得出现**：排除清单。版本号与更新日志内容默认归入此项。

在姊妹仓库之间，只迁移已获批准的视觉系统约束。每个仓库都要重建其主张、语言、用途与排除项。

## 两次否决就是硬停

数的是对观感的否决，不是对内容的否决。第二次之后，停止生成并重新对齐：重述那一句话，询问要并列哪张既有图片，确认排除清单。第三次盲目重生成等于把否决当作参数噪音，而它之后的版本可能比之前更差，这就是什么都没锚定的信号。

当某个版本部分正确时，在再次生成之前，先说出哪一部分是存活下来的。「保留构图，改配色」会收敛；「让它更好」不会。

## 装饰债

每一个标记都必须编码信息。在展示输出之前，扫一遍以下项：

- **对每条规则、边框、画框与分隔做「可移除测试」。** 如果删掉它不损失任何信息，那它就是装饰。
- **箭头用最小可读尺寸**，不是生成器的默认尺寸。过大的箭头看起来像剪贴画，是最常见的单项否决原因。
- **Logo 放在透明或匹配的底色上。** 深色底上 logo 周围有一圈白晕，说明源图带白底；去修源图，不要盖上去。
- **纯色域。** 图表里的渐变、辉光与投影添加了不承载意义的纵深，并弄脏最暗的区域。
- **线条数量。** 连接线与分隔线的增殖速度超过它们承载的信息；如果两个盒子相邻，相邻本身已经说明了关系。

## 把它限定在事物的本质

常青素材描述的是产品，不是某个版本。默认把版本字符串、更新日志条目与「new in」式框定留在相邻文本里。当用户明确要求一张发布卡片或其他发布专属素材时，纳入所要求的发布内容，并把其更短的保鲜期视为有意为之。
