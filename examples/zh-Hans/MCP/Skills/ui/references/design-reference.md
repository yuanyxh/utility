# 设计参考

## 技术栈冲突

以下组合会产生静默失败或前后不一致的输出。绝不要组合使用：

| 绝不要组合使用 | 原因 |
|---|---|
| 同一元素上 Tailwind + CSS Modules | 特异性冲突，层叠不可预测 |
| 同一元素上 Framer Motion + CSS transitions | 对同一属性双重动画会造成卡顿 |
| styled-components 或 emotion + Tailwind | 两套竞争的类系统争夺同一个 DOM 节点 |
| 一个项目里 Heroicons + Lucide + Font Awesome | 视觉不一致、尺寸不匹配、包体积膨胀 |
| 多个 Google 字体族作展示字体 | 彼此竞争的个性互相抵消 |
| 毛玻璃 backdrop-filter + 实心 `border: 1px solid` | 实心描边会击碎分层纵深的错觉 |
| 深色背景 + 全不透明度的 `#ffffff` 文本 | 过于刺眼；改用 `rgba(255,255,255,0.85)` 或 `#f0f0f0` |
| Tailwind v4 `@theme` + 动态构造的类名 | `@theme` token 以 JIT 方式生成工具类；如果类名由变量拼出、或未出现在被扫描的源码中，该类会被清除、样式静默消失。修法：源文件里用静态类名，加入 `safelist`，或在 `:root` 定义自定义颜色 + 在 `tailwind.config.js` 的 `extend.colors` 里定义，而不是用 `@theme` |

在写第一个组件之前，先点明本项目唯一的 CSS 策略：只用 Tailwind、只用 CSS Modules，或只用 CSS-in-JS。不要偏离它。

## 常见陷阱

提交之前，检查以下项是否有任何一项是在无意中溜进来的：

- 白色之上的紫色或蓝色渐变作为 hero 背景
- 三段式 hero：大标题、一行副文、两个并排的 CTA 按钮
- 一组圆角相同、投影相同、内边距相同的卡片网格
- 顶部导航栏：logo 在左、链接居中、主操作在最右
- 在白色与 `#f9f9f9` 之间交替的区块
- 一个居中的图标或插画，叠在标题之上、标题又叠在段落之上
- 一个四列、各列权重相等的页脚

任何这些，只要是有意服务于设计的，都可以出现。它们不能默认出现。

最终测试：如果你换进完全不同的内容，布局不做改动依然说得通，那你做的是一个模板，不是一个设计。重做它。

## 内容真实性

看起来真实、实际却不真实的占位文案，在用户读到的那一刻就会击碎幻觉。交接前应用这些规则。

**示例数据：**
- 不要通用名字：不要 John Doe、Jane Smith、Alex Johnson，或任何读起来像填充的名字+姓氏组合。使用文化多样、有真实具体性的名字（例如 Priya Mehta、Lars Eriksson、Nia Okafor）。
- 不要通用公司名：不要 Acme Corp、Nexus、SmartFlow、TechCorp、Initech。选带领域的名字（例如 Meridian Logistics、Hokkaido Ceramics、Vantage Bioworks）。
- 不要 Lorem Ipsum。写简短的、与布局阅读难度匹配的真实文案。
- 数据样本里不要用整数。`99.99%` 可用率、`50%` 转化率、`$100.00` MRR 看起来就是合成的。改用自然的值：`99.94%`、`47.2%`、`$99.00`。
- 多个头像实例不得共用同一张图。多个博客文章或活动卡片不得共用同一个日期。

**UI 文案：**
- 所有标题用句首大写（sentence case）。每个标题都首字母大写（Title Case）是正文里最常见的 AI 破绽。
- 从成功状态里去掉感叹号（「Saved!」→「Saved」，「Done!」→「Done」）。`!` 留给真正紧急的情况。
- 错误信息绝不要以「Oops!」开头。它读起来像是居高临下。
- 错误信息里不要用被动语态（「Something went wrong」→「We couldn't load your data. Try refreshing.」）。
- hero 文案、CTA 与功能描述中禁用的 AI 营销词：Elevate、Seamless、Unleash、Delve、Tapestry、Game-changer、Next-Gen、「In the world of...」。这些词对产品什么也没传达。改为点明具体的价值。

## 用占位符，而非仿制品

当某个图标、图片或组件不可得时：用占位符。在 hi-fi 设计里，一个带标注的占位符永远好过对真物的低质量模仿。例子：hero 图用灰色矩形、缺失的 logo 用字母组合字标、尚未设计的组件用虚线边框。

绝不要用内联 SVG 去画插画式图像。SVG 用于图标与几何形状。对摄影、插画或产品图，用占位符并请用户提供真实素材。

## 生产质量基线

交接前检查。无障碍与 CSS 模式禁令不可让步；下面其余的都是服务于已锁定方向的手艺细节。

> 把下面各节当作手艺细节，而非默认值。仅当它们服务于已锁定的视觉方向时才应用。如果去掉某个细节完全不改变界面给人的感觉，就别加它。

### 无障碍
- 只有图标的按钮需要 `aria-label`
- 动作用 `<button>`，导航用 `<a>`（不是 `<div onClick>`）
- 图片需要 `alt`（装饰性的用 `alt=""`）
- 可见的 focus 状态：`focus-visible:ring-*` 或等价物；绝不要在没有替代方案的情况下用 `outline: none`

### 动效
- 尊重 `prefers-reduced-motion`：设置时禁用或减少动画
- 只对 `transform`/`opacity` 做动画（对合成器友好，不触发布局抖动）
- 不要回弹或弹性缓动：真实物体是平滑减速的；用指数型 ease-out（`ease-out-quart`、`ease-out-quint`，或 `cubic-bezier(0.16,1,0.3,1)`）
- 可中断动画：交互状态变化（hover、toggle、开合）优先用 CSS transitions，因为它们会在动画中途重新定向；把关键帧动画留给只运行一次的编排式序列（例如交错式的页面入场）
- 交错入场：把内容切成语义块，间隔约 100ms；标题切到词一级，间隔约 80ms；典型的入场用 `opacity: 0 → 1`、`translateY(12px) → 0` 与 `blur(4px) → 0`
- 微妙的退场：用一个小的固定 `translateY(-12px)`，而不是整段高度；时长保持约 150ms `ease-in`，比入场更短更柔
- 语境化图标切换：用 `scale: 0.25 → 1`、`opacity: 0 → 1` 与 `blur: 4px → 0px` 做动画。用弹簧库时：`{ type: "spring", duration: 0.3, bounce: 0 }`。不用时：让两个图标都留在 DOM 里（一个绝对定位），用 CSS 以 `cubic-bezier(0.2, 0, 0, 1)` 交叉淡入淡出。除非旋转在语义上有意义（例如一个指示方向变化的 chevron），否则不要旋转
- 按下缩放：按钮在 active/按下时经 CSS transitions 用 `scale(0.96)`，以便按下动作可被中断；当动效会造成干扰时，加一个 `static` prop 予以禁用
- 页面加载防护：对 toggle、标签页与图标切换这类动画存在性包裹器使用 `initial={false}`，以防首次渲染时触发入场动画；不要把它用于有意的页面加载入场序列

### 性能
- transition 具体性：绝不用 `transition: all`；列出确切的属性（例如 `transition-property: scale, opacity`）。Tailwind 的 `transition-transform` 覆盖 `transform, translate, scale, rotate`；混用属性时用 `transition-[scale,opacity,filter]`
- GPU 合成：只对 `transform`、`opacity` 或 `filter` 使用 `will-change`。绝不用 `will-change: all`。只在察觉首帧卡顿时加；不要预防性地给每个元素都加
- 图片：显式的 `width` 与 `height`（防止布局偏移）
- 首屏之外的图片：`loading="lazy"`
- 关键字体：`font-display: swap`

### 触摸与移动端
- `touch-action: manipulation`（防止双击缩放的延迟）
- 满幅出血布局：带刘海设备用 `env(safe-area-inset-*)`
- 模态与抽屉：`overscroll-behavior: contain`
- hover 防护：用 `@media(hover:hover)` 包裹交互式 hover 状态，让它们只作用于指针设备、而不是触摸屏。Tailwind：`[@media(hover:hover)]:hover:bg-...`。没有它，移动端被点过的元素会保持永久 hover 状态，直到下一次点别处。

### 排版细节
- 文本换行：标题与短文本块（Chromium 中 ≤6 行，Firefox 中 ≤10 行）用 `text-wrap: balance`；正文段落与较长文本用 `text-wrap: pretty`；代码块与预格式化文本保持默认
- 字体平滑：在根布局上应用一次 `-webkit-font-smoothing: antialiased; -moz-osx-font-smoothing: grayscale`（仅 macOS）
- 等宽数字：计数器、计时器、价格、数值列，或任何动态更新的数字，用 `font-variant-numeric: tabular-nums`
- 字距随字号缩放：展示字体需要负字距，才显得是被精心调校过的、而不是被拉伸的。两个档位：展示字号（32px 及以上）约 -0.022em，中段（20–28px）约 -0.012em，16px 及以下为正常。应用于任何展示字重的字体，而不只是几何无衬线。大标题上的正字距永远是错的。

### 表面
- 同心圆角：计算 `outerRadius = innerRadius + padding`，让嵌套圆角显得是有意的、而不是机械的；如果内边距超过 `24px`，就把各层当作独立表面，各自选圆角
- 光学对齐：靠眼睛微调图标，而不只是靠数学，让按钮显得居中；带文字和图标的按钮，图标那一侧内边距略小（例如 `pl-4 pr-3.5`）；播放三角与不对称图标应向较重的一侧偏移 `1px`-`2px`，或直接修 SVG
- 阴影优于描边：卡片、按钮与抬升元素上用分层的 `box-shadow` 制造纵深，让表面显得被托起、而不是被围栏围住；把真正的 `border` 留给分隔线、表格单元格与布局分隔（主要适用于浅色模式；深色表面上见下文深色模式表面层级规则）
- 图片描边：加一道微妙的 inset 描边，让图片自带纵深又不改变布局尺寸：`outline: 1px solid rgba(0,0,0,0.1); outline-offset: -1px`（浅色）或 `outline: 1px solid rgba(255,255,255,0.1); outline-offset: -1px`（深色）
- 最小点击区域：让每个交互目标至少 40×40px，即使小控件也显得宽裕而精准；可见元素更小时用居中的伪元素扩展，且绝不要让两个交互元素的点击区域重叠
- 多卡片对齐：在卡片组里，把所有 CTA 按钮底部对齐，让卡片间的高度差异不会造成参差不齐的动作行。在定价或对比卡片里，把功能列表项在所有列上对齐到同一个 Y 原点。在并排面板（推荐语、套餐、功能拆解）里，标题、描述、价格与操作按钮必须在整行上共享基线。区块的顶部与底部内边距不必对称：光学平衡往往需要底部内边距比顶部大 20-25%。把正文段落宽度限制在约 65 字符（ch），以维持舒适的阅读行长。
- 浅色模式 App 表面层级：相邻的嵌套表面必须在视觉上可区分。下限：侧边栏与主区域之间、主区域与卡片之间至少 4% 明度的背景色分级；或抬升卡片上至少 `0 1px 3px rgba(0,0,0,0.10)` 的阴影。近白背景上的白卡片配 `box-shadow: 0 1px 2px rgba(0,0,0,0.05)` 是看不见的 -- 那不是纵深，是噪音。
- 深色模式表面层级：页面画布是近黑实色（例如 `#08090a`）。海拔通过在画布上叠加半透明白色来表达：卡片 `rgba(255,255,255,0.02)`、抬升表面 `0.04`、醒目面板 `0.05`。描边遵循同样的逻辑：微妙的用 `rgba(255,255,255,0.05)`，标准的用 `0.08`。传统投影（深色叠深色）几乎不可见；在深色表面上，借背景不透明度做明度分级才是主要的纵深线索。
- 圆角系统：在方向锁定阶段就定义一套命名的圆角刻度，而不是随手取值。最小刻度是 3–4 档（例如 `{4px, 8px, 12px, pill}`）；更丰富的系统可能到 6–8 档。关键在于在第一个组件之前就锁定一套命名的取值，让所有表面说同一种空间语言 -- 而不是覆盖每一种可能的圆角值。

### 加入既有 UI

扩展既有界面时，先花时间理解它的视觉语汇。在写第一行新代码之前，匹配以下所有项：
- 文案语气与阅读难度（技术向？随意？有力？）
- 色板与语义色角色（哪些 token 表示「危险」「成功」「弱化」）
- hover 与点击状态：缩放、颜色偏移、下划线、背景填充
- 动效风格：时长、缓动、交互是回弹还是严格 ease-out
- 阴影与卡片处理：哪些表面被抬升，哪些是齐平的
- 布局密度与留白节奏
- 圆角选择，以及按钮是胶囊、方形，还是某个具体的固定值

如果换上不同的内容会让新组件显得格格不入，那就是语汇匹配得不够到位。

### 响应式与屏幕验证
- 验证渲染出的界面，而不是一次类型检查或 CSS 平衡读取。若干回归（过早折行、孤立的间隔点、表格溢出）在源码里看不见，只在渲染中显现。在每个已发布语言下，于手机（375px，按钮另测 320px）与桌面（1280px）宽度截图。
- 行尾孤字：通过收紧文案让文本块重新平衡来消除 1-2 词的末行，而不是加一个 `max-width` 上限（比其容器还窄的上限会提前折行、在右侧留下空白，读起来像一次过早的断行）。客观地检测：标记任何末行不足其最宽行约 13% 的文本块；靠肉眼会漏掉它们，而嵌套的 `<code>` 又会让它们躲过 grep。
- 移动端 CTA 静置状态：自然宽度，与周边文本边缘左对齐，高度不变。居中读起来像漂浮；满宽 `flex: 1` 读起来笨重；为了缓解「太满」的感觉而降低按钮高度，是把宽度问题当成高度问题来治。
- 间距是一个系统，不是一个逐间隙的取值。把区块间距当作一条响应式阶梯来跑；当页面读起来太空或太紧时，在所有断点上用同一个系数整体缩放整套取值，而不是调某一个间隙。经调整后仍存活的非对称就是结构性的。
- 长文与文档界面保持轻量：一个无边框的上/下一页文本翻页器（不是带边框的卡片），侧边栏激活态用细轨而不是实心块，构建期零运行时 JS 的代码高亮（烘焙静态 span，纯代码保持为源）优于随包发布的高亮器。

## 要拒绝的反射性字体

LLM 之所以默认用这些，是因为它们主导了训练数据。用它们等于在说「没做任何决定」。改从有清晰声音的字库中挑选。禁令针对的是把其当作展示字体的反射性使用；有依据的产品 UI 使用（例如密集数据表用 Inter）在给出理由的前提下是允许的。这份清单并不详尽 -- 任何无理由反射性使用的字体都算。

拒绝：Inter、DM Sans、DM Serif Display、DM Serif Text、Outfit、Plus Jakarta Sans、Instrument Sans、Instrument Serif、Space Grotesk、Space Mono、IBM Plex Sans、IBM Plex Serif、IBM Plex Mono、Syne、Fraunces、Newsreader、Lora、Crimson Pro、Crimson Text、Playfair Display、Cormorant、Cormorant Garamond。

## 字体选择流程

1. 写下三个描述品牌的词（例如「精确、极简、快速」）。
2. 说出你反射性会去够的三个字体。
3. 全部否决。
4. 从一个有名字的字库（Klim、Commercial Type、Colophon、Grilli Type、OH no Type、Village 等）里挑一款字体，或挑一个性格清晰、与品牌词契合的开源选项。要能用一句话解释为什么是这一款字体。

## CJK 与多语言排版

当界面把中文、日文或韩文与拉丁文混排时，只面向拉丁文的排版规则会静默地弄坏 CJK 文本。交接前应用这些：

- **字体栈里拉丁字体在前，系统 CJK 字体在后**，让每种文字都用正确的字形渲染：`font-family: -apple-system, "SF Pro Text", "PingFang SC", "Noto Sans SC", sans-serif;`。拉丁文串用拉丁字体；汉字回落到 CJK 字体。
- **给 CJK 正文比拉丁文更大的行高**：阅读用大约 1.7–1.8。密集的汉字比适合拉丁正文的 1.4–1.5 需要更多纵向空间。
- **给文本串打上 `lang="zh"` / `lang="ja"` / `lang="en"` 标记**，让浏览器挑对字体与断行。混排语言的段落没有它就会断得很难看。
- **衬线阅读模式需要显式的 CJK 衬线回落。** 大多数拉丁「阅读衬线」网页字体不含 CJK 字形，所以一个衬线开关会静默地把中文掉回无衬线、看起来像坏了。把它们配对：`"Newsreader", "Songti SC", "Noto Serif SC", serif`。
- **不要给 CJK 文本串应用负字距。** 上文的展示字体负字距规则只适用于拉丁文；收紧汉字的字距会让字形局促、读起来像渲染 bug。把字距限定在 `lang="en"` 的文本串上。

## 色彩系统：OKLCH 规则

- 用 OKLCH 而不是 HSL。OKLCH 在感知上是均匀的：相同的数值变化在整个色域上产生相同的感知变化。
- 当明度趋近两端时降低彩度。85% 明度时彩度约 0.08 就够；推到 0.15 会显得扎眼。15% 明度时同样收紧彩度。
- 把中性色朝品牌色相染一点，彩度 0.005 到 0.01。即使这么微弱也是可感知的，并制造潜意识的凝聚力。
- 60-30-10 说的是视觉重量，不是像素数量。60% 中性/表面，30% 次级文本与描边，10% 强调。
- 绝不要在有色背景上用灰色文本。改用背景色相的一个降低明度的色调。

## 主题矩阵

基于受众与场景深思熟虑地选浅色或深色。两者都不是默认。

| 场景 | 方向 | 原因 |
|---|---|---|
| 交易或分析看板、夜班使用 | 深色 | 数据密度高；长时间会话中减少眩光 |
| 儿童阅读或学习 App | 浅色 | 亲和，对对比敏感度仍在发育的眼睛负担低 |
| 企业 SRE 或可观测性工具 | 深色 | 操作员场景；深色表面在弱光 NOC 房间里一眼可读 |
| 周末规划、食谱、手账 | 浅色 | 白天环境使用；浅色显得随意、平易近人 |
| 音乐播放器或媒体浏览器 | 深色 | 内容优先；深色表面后退，让媒体跳出来 |
| 医院或临床患者门户 | 浅色 | 信任与可读性至上；临床联想偏好浅色 |
| 复古或手作品牌站点 | 奶油色/暖浅色 | 深色会与模拟材质的指涉相冲突 |

如果答案无法从场景中一眼看出，默认浅色。如果用户的场景暗示两种模式都要，先交付浅色，再在其上叠加深色模式 token。

## 绝对禁令（CSS 模式层面）

这些模式出现在多数 AI 生成的界面里。每一条都有一个具体的改写。并不详尽 -- 任何作为无脑默认、而非有意选择来应用的 CSS 模式都属于同类。

| 模式 | 原因 | 改写 |
|---|---|---|
| 宽于 1px 的 `border-left` 或 `border-right` 作区块强调 | 管理与看板 UI 里被滥用得最多的「设计点缀」；超出发丝线分隔之外的任何粗细看起来都像失误 | 改元素结构：改用彩色圆点、短水平分隔线、背景色块，或一次字重变化 |
| `background-clip: text` 渐变文字 | 装饰性而非有意义；AI 设计破绽之首；打印或高对比模式下不可读 | 用实心品牌色、带色调的中性色，或字重来强调 |
| 把 `backdrop-filter: blur` 毛玻璃当默认卡片表面 | 在低功耗设备上开销大；被滥用；实心描边会击碎分层纵深的错觉 | 改用背景色分级与 `box-shadow` 做抬升表面 |
| 紫到蓝渐变，或深色上的青色强调系统 | 典型的「AI 设计」色板；对品牌什么也没传达 | 用上文 OKLCH 规则从品牌词出发挑一套色板 |
| 带 `box-shadow` 的通用圆角矩形卡片作默认容器 | 模板化思维；不论层级给每种内容套同一个容器 | 默认用无卡片区块；仅当内容类型需要时才加卡片处理 |
| 用模态作溢出 UI 的偷懒出口 | 打断流程并破坏浏览器后退；在本该用内联展开、抽屉或独立页面时被使用 | 内联展开、详情面板，或专门路由；仅当操作确实需要焦点锁定时才用模态 |
| `transition: all`，或给宽/高/内边距/外边距做动画 | 强迫浏览器每帧重算布局 | 列出确切属性（`transition-property: transform, opacity`）；高度揭示用 `grid-template-rows: 0fr to 1fr` |

## 参考素材优先级

当参考 UI 的源码与截图都可得时：读代码。源文件包含精确的 token 取值；截图需要靠猜。从写下来的东西重建，而不是从看得见的东西。

当只提供一个 URL 时：抓取它只会返回抽出的文本，不含布局信息。对视觉参考（「让它看起来像 X」），索取截图，而不是从剥离后的 HTML 去推断视觉设计。

## DESIGN.md 骨架（可选，生产级 UI）

对多页或生产级 UI，在写第一个组件之前，先输出一份简短的 `DESIGN.md` 式摘要。这会强制把本会被隐式留白的决策逐一列出，并让用户能尽早纠正方向。共九节：

1. **视觉主题与氛围** - 用 2-3 句话说明气质、密度、设计哲学
2. **色板与角色** - 每个颜色 token 的语义名 + 取值 + 功能角色
3. **排版规则** - 字体族、字号刻度、字重刻度、行高、字距；超过 4 级时用表格
4. **组件样式** - 按钮（所有状态）、卡片（如使用）、输入框、导航；每个都连状态（默认、hover、active、disabled）一起描述
5. **布局原则** - 间距刻度、网格列数、留白哲学
6. **纵深与海拔** - 阴影系统或背景色分级系统；描述每一层
7. **Do 与 Don't** - 5 到 10 条针对本项目的护栏，而不是通用规则
8. **响应式行为** - 断点、导航如何收起、触摸目标下限
9. **Agent 提示词指南** - 一份快捷颜色参考（名称:取值 对）+ 3 到 5 个可直接粘进后续请求的示例组件提示词。提示词必须足够具体，无需再查即可执行：每个取值、每个圆角、每个字距、每个字重都内联进去。示例标准（取值仅作示意，用项目自己的 token）：「在 `{bg-canvas}` 上创建 hero，标题 48px、字重 600、行高 1.00、字距 -0.022em、颜色 `{text-primary}`，CTA 用 `{accent}`、圆角 `{btn-radius}`」；到这个具体程度，而不是「用主色和 CTA 按钮的 hero」

对单个组件或快速原型，跳过这一步。SKILL.md 里的三行命题就够了。

## 交接前清单：策略性遗漏

这些是 AI 生成 UI 中最常缺失的项，因为它们需要的是有意的产品思考，而不是视觉判断。每次交接前都过一遍。

- [ ] **自定义 404 页**：一个通用的框架 404 是坏掉的体验。做一个带品牌感、并有清晰返回路径（首页链接、搜索，或最常用的导航项）的页面。
- [ ] **返回导航**：每个能通过用户操作到达的页面都必须有一条清晰、可用的返回路径。死胡同页面（详情视图、确认屏、只能用模态的流程）是 UX 失败。
- [ ] **表单客户端校验**：邮箱字段在提交前校验格式；必填项显示行内错误；错误信息出现在字段旁，而不只在表单顶部。
- [ ] **跳转到内容链接**：一个视觉隐藏的 `<a href="#main-content">Skip to main content</a>`，作为文档中第一个可聚焦元素。键盘无障碍所需。
- [ ] **Cookie 同意**：如果产品在欧盟或加州运营，cookie 同意 UI 不是可选项。把实现限定在相应辖区。
- [ ] **页脚隐私与条款链接**：每个产品页都需要这些。它们缺席等于在说「demo」，而不是「产品」。

这些不是视觉打磨项。它们是 demo 与可交付产品之间的区别。

## AI 味测试

一个陌生人瞥一眼首屏，会不会立刻说「这是 AI 做的」？如果会，那就是已确定的方向锁定得不够。常见的罪魁：反射性字体、默认紫色强调、居中 hero 加下方通用卡片网格。修改排版、色彩系统或布局，直到答案翻转。

## App 外壳规则

构建「侧边栏 + 主工作区」布局（Slack、Linear、Notion 这一类）时：
- 装饰性背景默认关闭
- 表面层级只使用背景色分级与阴影
- 所有交互元素用动效一节里的标准按下缩放（active/按下时 `scale(0.96)`）
- 同一组件类型内的按钮圆角保持一致（挑一种：胶囊、方形，或一个固定值，不要混用）
- 在第一个组件之前锁定一套命名的圆角刻度（见上文圆角系统）

## 选项指南

被要求给出设计方案时，至少给出 3 个跨越真正不同维度的变体：

- **可变的维度**：视觉密度、排版性格、色彩温度、布局结构、动效性格、装饰多寡、抽象程度
- **混合手法**：一个紧贴既有惯例，一个以新方式重新演绎品牌 DNA，一个刻意出人意料
- **从稳妥到大胆递进**：第一个选项安全、易懂；后续选项推进得更远
- 仅靠强调色区分的三个选项不算三个变体。要变的是布局、字体、动效、表面处理。
