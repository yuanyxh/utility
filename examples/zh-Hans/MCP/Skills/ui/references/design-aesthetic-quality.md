# 设计审美质量与生产结构

## App 外壳规则

构建「侧边栏 + 主工作区」布局（Slack、Linear、Notion 这一类）时：
- 装饰性背景默认关闭
- 表面层级只使用背景色分级与阴影
- 所有交互元素加上 `active:scale-95`
- 同一组件类型内的按钮圆角保持一致（挑一种：胶囊、方形，或一个固定值，不要混用）
- 在第一个组件之前，先确定一套命名好的圆角刻度

## 选项指南

被要求给出设计方案时，至少给出 3 个跨越真正不同维度的变体：

- **可变的维度**：视觉密度、排版性格、色彩温度、布局结构、动效性格、装饰多寡、抽象程度
- **混合手法**：一个选项紧贴既有惯例，一个重新演绎品牌 DNA，一个刻意出人意料
- **从稳妥到大胆递进**：第一个选项安全、易懂；后续选项推进得更远
- 仅靠强调色区分的三个选项不算三个变体。要变的是布局、字体、动效、表面处理。

## DESIGN.md 骨架（可选，生产级 UI）

对多页或生产级 UI，在写第一个组件之前，先输出一份简短的 `DESIGN.md` 式摘要。共九节：

1. **视觉主题与氛围**：用 2-3 句话说明气质、密度、设计哲学
2. **色板与角色**：每个颜色 token 的语义名 + 取值 + 功能角色
3. **排版规则**：字体族、字号刻度、字重刻度、行高、字距
4. **组件样式**：按钮（所有状态）、卡片（如使用）、输入框、导航
5. **布局原则**：间距刻度、网格列数、留白哲学
6. **纵深与海拔**：阴影系统或背景色分级系统；描述每一层
7. **Do 与 Don't**：5 到 10 条针对本项目的护栏
8. **响应式行为**：断点、导航如何收起、触摸目标下限
9. **Agent 提示词指南**：颜色参考（名称:取值 对）+ 3-5 个示例组件提示词，所有取值都内联进去

对单个组件或快速原型，跳过这一步。三行命题就够了。

## 交接前清单：策略性遗漏

AI 生成 UI 中最常缺失的项：

- [ ] **自定义 404 页**：一个带品牌感、且有清晰返回路径的页面
- [ ] **返回导航**：每个能通过用户操作到达的页面都必须有返回路径
- [ ] **表单客户端校验**：在每个字段旁显示行内错误
- [ ] **跳转到内容链接**：视觉隐藏的 `<a href="#main-content">Skip to main content</a>`，作为第一个可聚焦元素
- [ ] **Cookie 同意**：面向欧盟或加州辖区
- [ ] **页脚隐私与条款链接**

这些不是打磨项。它们是 demo 与可交付产品之间的区别。

## 参考素材优先级

当源码与截图都可得时：读代码。源文件包含精确的 token 取值；截图需要靠猜。

当只提供一个 URL 时：抓取只会返回抽出的文本，不含布局信息。对视觉参考，索取截图，而不是从剥离后的 HTML 去推断。

## 加入既有 UI

扩展既有界面时，先理解它的视觉语汇。在写第一行新代码之前，匹配以下所有项：
- 文案语气与阅读难度
- 色板与语义色角色
- hover 与点击状态：缩放、颜色偏移、下划线、背景填充
- 动效风格：时长、缓动、交互是回弹还是 ease-out
- 阴影与卡片处理
- 布局密度与留白节奏
- 圆角选择

如果换上不同的内容会让新组件显得格格不入，那就是语汇匹配得不够到位。
