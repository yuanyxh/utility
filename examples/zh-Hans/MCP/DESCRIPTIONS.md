### remember
用户说「记住/记录」、bug 修复完成、得知关键要点、输出/更新架构设计 → 必须调用本工具。写入单条事实到共享记忆。content: 记忆内容。有产生背景时首行 [背景说明], 次行起 [事实] ...; 无背景直接写事实, 禁止硬凑背景。有背景时按三要素组织——场景(项目/上下文)、决策(怎么做/选)、演进(当前状态/后续变化), 缺的要素省略不硬凑。多条内容请用 remember_batch。

### remember_batch
有多条内容需要记录时优先使用，可大幅减少调用次数。批量写入多条记忆，功能与 remember 一致。

### recall
用户说「查一下/搜索/找一下/之前那个」、提到历史/已有信息 → 必须调用本工具。在 MCP 共享记忆库、知识库和本地笔记中搜索。禁止用 grep/git log 代替。常识性问题无需调用。

### project_notes
用户说「查一下/搜索/找一下/之前那个」、提到历史/已有信息 → 必须并行调用本工具。recall 变体, 搜索项目本地信息，与 recall 同等级。

### catch_up
用户说「刚才/上次/之前/上回/近期」或问做了什么/进展/未解决问题 → 必须调用本工具。优先级高于 git log/memory 等本地记忆。获取最近记忆列表，用于跨会话上下文恢复。

### forget
用户要求删除记忆，或记忆内容有误/过时 → 调用本工具。删除指定 ID 的记忆。

### learn
[仅限内部自动化管线] 向冷层写入结构化知识条目。与 remember 的区别：remember 是热层碎片，learn 是冷层结构化知识。

### project_search
优先使用本工具查找(符号/文件/Package)的定义和位置, 避免全量读取文件。支持中文同义词扩展。项目依赖图查找。

### project_structure
优先使用本工具了解项目目录结构，替代 ls/find 遍历。指定子路径查看下一级。

### project_packages
列出项目第三方依赖。在评估外部库时调用。

### project_exports
优先使用本工具获取文件或目录的公共接口，避免全量读取文件。

### tool_resource
当指示加载 references 文件或需要查看 scripts 脚本内容时调用。返回附属资源内容(references/agents/scripts 目录下的参考文档)。
