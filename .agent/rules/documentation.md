# 文档规则

## DOC-01 文档按用途分型

**规则**：文档分为教程、操作指南、参考、解释四类；教程用于学习，操作指南用于完成任务，参考用于查询事实，解释用于理解原因。一篇只服务一类。

**禁止**：在操作指南里展开设计原理，或在参考文档里嵌入完整教程。

**验证**：每篇文档能用一句话说明读者与用途，且只属于一类。

## DOC-02 先说明适用性

**规则**：开头写目的、适用读者与前置条件；正文步骤与参考信息分离；结尾给验证结果或下一步。

**禁止**：标题下直接进入细节，读者无法判断是否适用。

**验证**：读者读完首段能判断该文档是否解决自己的问题。

## DOC-03 目录与命名

**规则**：按读者或文档类型分目录；文件名小写、连字符分隔、语义明确；每篇文档有唯一入口。

**禁止**：所有文档堆在根目录或单个 README。

**验证**：按目录可在十分钟内定位目标文档。

## DOC-04 文档与代码同版本

**规则**：文档与对应代码在同一提交更新；变更记录标注版本与日期。

**禁止**：文档长期落后于实现。

**验证**：代码变更清单与文档变更清单同步。

## DOC-05 标题层级

**规则**：一个文件只有一个一级标题；标题层级逐级递进；同一页标题文本唯一；用标题而非加粗表达层级。

**禁止**：跳过层级、重复标题、用加粗文本冒充标题。

**验证**：文档检查无标题层级、重复标题与标题格式类告警。

## DOC-06 代码块

**规则**：代码、命令、配置与输出使用围栏代码块并标注语言；标识符与命令片段用行内代码。

**禁止**：缩进式代码块、无语言标注、把日志与结果混在同一块。

**验证**：代码块均可高亮，内容可直接复制执行。

## DOC-07 链接

**规则**：链接文本描述目标内容；站内链接用相对路径；外部链接给完整 URL。

**禁止**：「点击这里」、裸 URL、指向本地路径或临时分支的绝对链接。

**验证**：链接检查通过；重命名标题后无断链。

## DOC-08 图片

**规则**：图片有替代文本；截图标注版本与状态；优先矢量或高分辨率图片。

**禁止**：无替代文本、过期截图、仅靠颜色传达信息。

**验证**：关闭图片后仍能理解文档内容。

## DOC-09 块结构与空白

**规则**：标题、列表、代码块、表格前后留空行；同一列表使用一致的符号与缩进；全项目统一一种换行策略。

**禁止**：混用列表符号、堆叠空行、行尾空格、换行策略混用。

**验证**：文档检查无块结构与空白类告警；diff 只反映语义变更。

## DOC-10 限制内嵌 HTML

**规则**：优先使用 Markdown 原生语法；确需 HTML 时限制在目标渲染器支持的标签内。

**禁止**：用 HTML 布局代替 Markdown 结构；依赖仅单一平台支持的标签。

**验证**：在目标渲染器与纯文本预览中结构一致。

## DOC-11 语态与句式

**规则**：使用第二人称、主动语态与短句；条件写在指令之前；标题与文档名使用句首大写。

**禁止**：被动语态堆叠、长难句、用「我们」指代读者。

**验证**：随机抽段能指出执行者与动作；标题大小写一致。

## DOC-12 术语一致

**规则**：同一概念全篇使用同一名称，首次出现给定义或中英对照；术语表集中维护。

**禁止**：同义词混用、缩写未定义。

**验证**：检索一个概念只得到一处定义。

## DOC-13 中文排版

**规则**：中文与英文、数字之间加空格；中文正文使用全角标点；代码、命令、路径、文件名保留原文；专有名词首次出现给中英对照。

**禁止**：中英文直接相连、中文正文使用半角标点、翻译代码标识符。

**验证**：抽查段落排版一致；代码块内容未被翻译或改写。

## DOC-14 检查进流水线

**规则**：Markdown 结构与排版规则落地为自动检查，纳入本地钩子与 CI，与代码检查同等级。

**禁止**：只靠人工记忆执行格式规范。

**验证**：不合规文档在提交或合并前被拦截。
